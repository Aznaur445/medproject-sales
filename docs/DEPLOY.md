# Установка сервиса: подробная инструкция

Инструкция написана для человека без опыта администрирования серверов. Делайте шаги строго по порядку. После каждого шага есть пункт **«✅ Проверка»**: не переходите дальше, пока проверка не прошла.

Если что-то пошло не так, сделайте скриншот или скопируйте текст ошибки и пришлите разработчику (в чат с Claude). Пароли и токены в чат **не присылайте**.

> Названия кнопок в панели Timeweb могут немного отличаться от написанных здесь: интерфейс иногда меняется. Ищите похожие по смыслу.

## Что получится в итоге

```
                Интернет
                    │
     crm.project-med.ru / status.project-med.ru
                    │
     ┌──────────────▼───────────────────────────┐
     │  VPS (Ubuntu) в Timeweb                    │
     │  Caddy (HTTPS) → панель, бот,              │
     │  обработчик задач, планировщик, Redis,     │
     │  мониторинг Uptime Kuma                    │
     └──────────────┬───────────────────────────┘
                    │ приватная сеть (закрыта от интернета)
     ┌──────────────▼───────────────────────────┐
     │  Управляемая база PostgreSQL Timeweb       │
     │  (ваша «Humble Erinome»)                   │
     └────────────────────────────────────────────┘
        + хранилище S3 Timeweb: копии бэкапов
        + почта Mail.ru: отправка КП
        + Telegram-бот: согласование
```

**Время:** 1,5–2 часа в первый раз.

**Понадобится:**
- компьютер (Windows 10/11 или Mac). С одного телефона тоже можно, см. примечание в шаге 2;
- доступ к панели Timeweb Cloud с положительным балансом;
- доступ к GitHub-аккаунту `Aznaur445`;
- телефон с Telegram;
- приложение для кодов входа на телефоне: **Яндекс Ключ** или **Google Authenticator** (бесплатные, есть в App Store).

## Шаг 2. SSH-ключ на вашем компьютере

SSH-ключ — это «электронный ключ» для входа на сервер вместо пароля. Его невозможно подобрать, поэтому это безопаснее пароля.

### Windows 10/11
1. Нажмите **Пуск**, наберите `PowerShell` и откройте **Windows PowerShell**.
2. Вставьте команду (в PowerShell вставка делается **правой кнопкой мыши**) и нажмите Enter:
   ```
   ssh-keygen -t ed25519 -C "medproject"
   ```
3. Программа задаст три вопроса. На каждый просто нажмите **Enter**: путь по умолчанию, пустая фраза-пароль, её повтор.
4. Выведите публичную часть ключа:
   ```
   type $env:USERPROFILE\.ssh\id_ed25519.pub
   ```
5. Появится одна длинная строка, начинающаяся с `ssh-ed25519 AAAA...`. Выделите её мышью целиком и скопируйте (Ctrl+C).

### Mac
1. Откройте **Терминал** (Cmd+Пробел, наберите «Терминал»).
2. Выполните:
   ```
   ssh-keygen -t ed25519 -C "medproject"
   ```
   На три вопроса нажмите **Enter**.
3. Скопируйте публичный ключ в буфер обмена:
   ```
   pbcopy < ~/.ssh/id_ed25519.pub
   ```

> **Важно:** файл `id_ed25519` **без** `.pub` — это секретная часть ключа. Никому её не отправляйте и никуда не вставляйте. Вставлять можно только строку из файла `.pub`.

> **Только телефон?** Установите на iPhone приложение **Termius**. В нём: Keychain → «+» → Generate Key → тип ED25519, затем «Export to clipboard» / «Copy public key». Дальше все команды из этой инструкции выполняются в Termius.

✅ **Проверка:** у вас скопирована строка вида `ssh-ed25519 AAAAC3Nza... medproject`.

## Шаг 3. Приватная сеть в Timeweb

Приватная сеть соединяет сервер и базу напрямую, минуя интернет. Тогда базу можно закрыть от внешнего мира.

1. Откройте панель Timeweb Cloud.
2. В левом меню найдите раздел **«Сети»** (иногда он называется **«Приватные сети»** или **VPC**).
3. Нажмите **«Создать сеть»**.
4. Регион выберите **тот же, где находится ваша база** «Humble Erinome»: регион виден в карточке базы, флажок 🇷🇺 и город.
5. Имя: `medproject`. Диапазон адресов оставьте по умолчанию.
6. Нажмите **«Создать»**.

> Если раздела сетей нет или база уже подключена к какой-то приватной сети, используйте ту сеть. Если приватную сеть подключить не получается, ничего страшного: сервис будет ходить в базу через интернет с шифрованием (см. шаг 4, вариант Б).

✅ **Проверка:** в списке сетей есть сеть `medproject` в нужном регионе.

## Шаг 4. Подготовка базы данных «Humble Erinome»

### 4.1. Проверьте версию PostgreSQL
1. Timeweb → **Базы данных** → нажмите на карточку **Humble Erinome**.
2. На странице базы найдите строку **«Версия»** или **PostgreSQL N**.
3. Подходят версии **14–18** (у вашей базы Humble Erinome — 18).

Если указан не PostgreSQL или версия выше 18, остановитесь и напишите разработчику.

### 4.2. Посмотрите, что уже лежит в базе
На странице базы откройте вкладку **«Базы данных»** (внутри одного сервера баз может быть несколько).
- Если там только служебная база (у Timeweb она обычно называется `default_db`) и вы уверены, что stroykontrol её не использует, можно создать рядом новую базу.
- **Ничего существующего не удаляйте.** Сервис будет работать в отдельной базе.

### 4.3. Создайте отдельную базу для сервиса
1. На вкладке **«Базы данных»** нажмите **«Добавить базу»** / **«Создать»**.
2. Имя: `medproject`.
3. Сохраните.

### 4.4. Создайте пользователя
1. Откройте вкладку **«Пользователи»** → **«Добавить пользователя»**.
2. Логин: `medproject`.
3. Пароль сгенерируйте длинный, из букв и цифр (кнопка генерации или менеджер паролей). Запишите в шпаргалку.
4. Права: доступ к базе `medproject`, **все привилегии** (чтение, запись, создание таблиц).
5. Сохраните.

> Если интерфейс не даёт создать пользователя, можно использовать пользователя по умолчанию (у Timeweb обычно `gen_user`). Его пароль показан на странице базы в разделе «Подключение».

### 4.5. Подключите базу к приватной сети
1. На странице базы найдите раздел **«Сеть»** / **«Приватная сеть»**.
2. Подключите сеть `medproject` из шага 3.
3. После подключения у базы появится **приватный IP** вида `192.168.0.5` или `10.x.x.x`. Запишите его в шпаргалку.

**Вариант Б (без приватной сети):** в разделе **«Подключение»** скопируйте **публичный адрес** (хост) и порт базы. В шпаргалке запишите его вместо приватного IP. Сервис подключится с обязательным шифрованием.

✅ **Проверка:** в шпаргалке записаны адрес базы, порт, имя базы `medproject`, пользователь и пароль.

## Шаг 5. Создайте сервер (VPS)

1. Timeweb → **Облачные серверы** → **«Создать»**.
2. **Регион:** тот же, что у базы и приватной сети.
3. **Образ / ОС:** **Ubuntu 24.04**.
4. **Конфигурация:** **2 vCPU, 4 ГБ RAM, диск 30–40 ГБ NVMe**. Меньше 4 ГБ памяти брать не стоит: генерация PDF и будущий разбор документов требуют памяти.
5. **Сеть:**
   - публичный IPv4 — **да**;
   - **приватная сеть** — выберите `medproject`.
6. **SSH-ключ:** нажмите «Добавить ключ», вставьте строку из шага 2, название `medproject`. Ключ должен быть **отмечен** для этого сервера.
7. **Защита от DDoS, бэкапы сервера** — по желанию. У сервиса свои бэкапы, но снимки сервера Timeweb не помешают.
8. Имя сервера: `medproject`.
9. Нажмите **«Заказать»** / **«Создать»** и подождите 1–3 минуты.
10. В карточке сервера появится **IP-адрес** (публичный, вида `85.193.x.x`). Запишите его в шпаргалку.

✅ **Проверка:** сервер в статусе «Работает», IP записан.

## Шаг 6. Домены (DNS-записи)

Нужно, чтобы адреса `crm.project-med.ru` (панель) и `status.project-med.ru` (мониторинг) вели на ваш сервер.

### Если домен `project-med.ru` в Timeweb (на скриншоте у вас есть раздел «Домены»)
1. Timeweb → **Домены** → `project-med.ru` → **DNS** / **«Настройки DNS»**.
2. Нажмите **«Добавить запись»**:
   - тип: **A**;
   - имя / поддомен: `crm`;
   - значение / IP: IP сервера из шага 5;
   - TTL: по умолчанию.
3. Добавьте вторую запись так же: тип **A**, имя `status`, тот же IP.
4. Сохраните.

### Если домен у другого регистратора (reg.ru, nic.ru и т.п.)
Сделайте те же две A-записи в разделе управления DNS у регистратора.

> Сайт `project-med.ru` эти записи **не затрагивают**: добавляются только новые поддомены.

✅ **Проверка** (через 5–30 минут): на компьютере выполните
```
ping crm.project-med.ru
```
В ответе должен быть IP вашего сервера. Если пишет «не удаётся найти узел», подождите ещё и повторите. Остановить ping: Ctrl+C.

## Шаг 7. Хранилище S3 для копий бэкапов

Каждую ночь сервис делает бэкап и кладёт копию сюда. Тогда данные переживут даже потерю сервера.

1. Timeweb → **Хранилище S3** (или **«Объектное хранилище»**) → **«Создать бакет»**.
2. Имя: например `medproject-backups-ВАШЕСЛОВО`. Имя должно быть уникальным, используйте латиницу, цифры и дефис.
3. Тип: **Приватный**.
4. Класс хранения: стандартный, размер: минимальный.
5. Создайте бакет.
6. В карточке бакета найдите **«Ключи доступа»** / **«Доступ»**. Скопируйте **Access Key** и **Secret Key** в шпаргалку.
7. Проверьте **адрес (endpoint)** и **регион**. Обычно это `https://s3.twcstorage.ru` и `ru-1`. Если на странице бакета указано иное, запишите то, что указано.

✅ **Проверка:** в шпаргалке есть имя бакета и оба ключа.

## Шаг 8. Telegram-бот

1. В Telegram найдите **@BotFather** (с синей галочкой) → нажмите **Start**.
2. Отправьте `/newbot`.
3. Введите имя бота, например `МедПроект Продажи`.
4. Введите username латиницей, он должен заканчиваться на `bot`, например `medproject_sales_bot`. Если имя занято, придумайте другое.
5. BotFather пришлёт **токен** вида `7123456789:AAH...`. Скопируйте его в шпаргалку. **Никому его не показывайте**: с токеном можно управлять ботом.
6. Найдите **@userinfobot** → **Start**. Он пришлёт ваш **Id**: число вроде `123456789`. Запишите его.

✅ **Проверка:** в шпаргалке есть токен и ваш ID.

## Шаг 9. Почта для отправки КП

### Вариант А (рекомендуется): ящик на своём домене `kp@project-med.ru`
Письма с корпоративного домена реже попадают в спам, а ящик не заблокируют за отправку КП незнакомым адресатам.

1. Откройте **biz.mail.ru** (VK WorkSpace / Почта Mail.ru для бизнеса) → **«Подключить домен»** → введите `project-med.ru`.
2. Сервис попросит подтвердить владение доменом. Обычно нужно добавить **TXT-запись** в DNS домена (как в шаге 6, только тип TXT, значение даст Mail.ru).
3. Затем добавьте **MX-записи**, которые покажет Mail.ru. Они нужны, чтобы на домен приходила почта.
   > ⚠️ Если на `project-med.ru` **уже** есть почта (Яндекс, Timeweb), смена MX-записей перенесёт её. В этом случае остановитесь и напишите разработчику: подберём вариант без поломки текущей почты.
4. Создайте ящик `kp@project-med.ru`, войдите в него.
5. Создайте **пароль для внешнего приложения**:
   - в почте откройте **Настройки** → **Безопасность** (или **«Пароли для внешних приложений»**);
   - **«Добавить»**, название `medproject`, доступ: **SMTP и IMAP** (полный доступ к почте);
   - скопируйте показанный пароль в шпаргалку. Он показывается **один раз**.

### Вариант Б (временно, для проверки): существующий ящик `med-project@bk.ru`
Подходит, чтобы проверить работу сервиса, но не для постоянной рассылки. Пароль приложения создаётся так же: Настройки → Безопасность → Пароли для внешних приложений.

✅ **Проверка:** в шпаргалке есть адрес почты и **пароль приложения** (это не обычный пароль от почты!).

## Шаг 10. Первый вход на сервер

1. Откройте PowerShell (Windows), Терминал (Mac) или Termius.
2. Выполните, подставив IP сервера:
   ```
   ssh root@IP_СЕРВЕРА
   ```
3. На вопрос `Are you sure you want to continue connecting (yes/no)?` наберите `yes` и нажмите Enter.
4. Вы на сервере, если видите строку вида:
   ```
   root@medproject:~#
   ```

> Если пишет `Permission denied (publickey)`, ключ из шага 2 не добавился к серверу. В карточке сервера Timeweb проверьте раздел SSH-ключей, или переустановите ОС с выбранным ключом. Временно можно войти через **«Консоль»** в карточке сервера (там вход по паролю root из письма Timeweb).

✅ **Проверка:** видите `root@...:~#`.

### Шаг 10.1. Проверьте, что сервер видит базу
Выполните, подставив адрес базы из шпаргалки:
```
apt-get update -qq && apt-get install -y -qq postgresql-client >/dev/null && psql "host=АДРЕС_БАЗЫ port=5432 dbname=medproject user=medproject sslmode=prefer" -c "select version();"
```
Команда спросит пароль пользователя базы. Вставьте его (при вводе символы не отображаются, это нормально) и нажмите Enter.

✅ **Проверка:** выводится строка `PostgreSQL 16.x ...` (или 14/15/17).
- `timeout` / `could not connect` — сервер и база не в одной приватной сети, или (вариант Б) у базы не включён публичный доступ.
- `password authentication failed` — неверный пользователь или пароль.
- `permission denied for database` — у пользователя нет прав на базу `medproject` (шаг 4.4).

## Шаг 11. Ключ доступа к репозиторию GitHub

Репозиторий приватный, поэтому серверу нужен свой ключ **только для чтения**.

1. На сервере выполните:
   ```
   ssh-keygen -t ed25519 -f ~/.ssh/medproject_deploy -N ""
   cat ~/.ssh/medproject_deploy.pub
   ```
2. Скопируйте выведенную строку `ssh-ed25519 AAAA... root@medproject`:
   - Windows PowerShell: выделите мышью, при выделении она копируется сама (или правой кнопкой);
   - Mac: выделите и нажмите Cmd+C.
3. Откройте в браузере **github.com/Aznaur445/medproject-sales** → вкладка **Settings** → слева **Deploy keys** → **Add deploy key**.
4. Title: `timeweb-server`. Key: вставьте строку. Галочку **Allow write access НЕ ставьте**. Нажмите **Add key**.
5. На сервере выполните:
   ```
   git config --global core.sshCommand "ssh -i ~/.ssh/medproject_deploy"
   git clone git@github.com:Aznaur445/medproject-sales.git /opt/medproject-sales
   ```
   На вопрос `Are you sure you want to continue connecting` ответьте `yes`.

✅ **Проверка:**
```
ls /opt/medproject-sales
```
Показывает папки `app`, `docs`, `scripts` и файлы `docker-compose.yml`, `README.md`.

```
cd /opt/medproject-sales
```

Скрипт работает 5–15 минут: сначала ставит программы, потом задаёт вопросы. Что отвечать:

| Вопрос скрипта | Что ввести |

| `Домен панели` | `crm.project-med.ru` |
| `Домен страницы мониторинга [status.project-med.ru]` | просто Enter |
| `E-mail для сертификатов HTTPS` | ваш e-mail (на него приходят уведомления о сертификатах) |
| `Токен Telegram-бота` | токен из шага 8 |
| `Ваш Telegram ID` | ID из шага 8 |
| `База данных: 1 — в Docker на этом сервере, 2 — управляемая база Timeweb Cloud` | `2` |
| `Адрес базы` | приватный IP базы (или публичный хост для варианта Б) |
| `Порт` | Enter (5432) или порт из Timeweb |
| `Имя базы` | Enter (`medproject`) |
| `Пользователь` | `medproject` (или `gen_user`) |
| `Пароль пользователя базы` | пароль из шага 4.4. Символы не отображаются, это нормально |
| `Создать владельца панели сейчас? yes/no` | `yes` |

| `Пароль (не меньше 12 символов)` и повтор | придумайте пароль для панели, запишите в шпаргалку |

В конце появится:
```
==> Готово
Панель:      https://crm.project-med.ru
Мониторинг:  https://status.project-med.ru
```

✅ **Проверка:**
```
docker compose ps
```
Все сервисы (`api`, `worker`, `scheduler`, `bot`, `redis`, `caddy`, `uptime-kuma`) должны быть в состоянии `Up`, многие с пометкой `(healthy)`. Проверить его можно командой `docker compose ps -a migrate`: статус должен быть `Exited (0)`.

> Если скрипт остановился с ошибкой, скопируйте последние 20–30 строк и пришлите разработчику. Повторный запуск `sudo ./scripts/install.sh` безопасен: сделанные шаги пропускаются.

## Шаг 13. Сохраните файл настроек `.env`

## Шаг 14. Почта и S3 в настройках

1. Откройте файл настроек в редакторе:
   ```
   nano /opt/medproject-sales/.env
   ```
2. Перемещайтесь стрелками. Найдите строки и впишите значения **после знака `=` без пробелов и кавычек**:
   ```
   MAIL_USER=kp@project-med.ru
   MAIL_APP_PASSWORD=пароль_приложения_из_шага_9
   MAIL_FROM_NAME=МедПроект

   S3_ENDPOINT_URL=https://s3.twcstorage.ru
   S3_REGION=ru-1
   S3_BUCKET=имя_бакета
   S3_ACCESS_KEY=ключ
   S3_SECRET_KEY=секретный_ключ
   ```
   Вставка текста: правая кнопка мыши (Windows), Cmd+V (Mac).
3. Сохраните: **Ctrl+O**, затем **Enter**. Выйдите: **Ctrl+X**.
4. Примените настройки:
   ```
   cd /opt/medproject-sales && docker compose up -d
   ```

✅ **Проверка:**
```
./scripts/backup.sh
```
В конце должен быть список, где бэкап есть и в `"local"`, и в `"s3"`:
```
{ "local": ["20261005-101500"], "s3": ["20261005-101500"] }
```
- Если `s3` пустой или есть ошибка с `S3`/`Access Denied`, проверьте ключи и имя бакета.

## Шаг 16. Настройки в панели

### 16.1. Реквизиты
**Настройки → Реквизиты ИП.** Заполните:
- Бренд: `МедПроект`;
- Полное наименование: `ИП Гамзатов Азнаур Артурович`;
- Краткое: `ИП Гамзатов А.А.`;
- ИНН, ОГРНИП, адрес, банк (`АО «ТБанк»`), БИК, расчётный счёт, корр. счёт;
- телефон, e-mail (который будет в КП), сайт `project-med.ru`, город.

Нажмите **«Сохранить реквизиты»**.

### 16.2. Тексты КП
**Настройки → Тексты КП.** Проверьте и поправьте под себя: вступление, срок выполнения, варианты оплаты (каждый с новой строки), гарантии, преимущества (каждое с новой строки), подпись. **«Сохранить тексты»**.

### 16.3. Расценки
Раздел **«Расценки»**:
1. **«Цена стандартного пакета по площади»** (АР, ЭОМ, ВК, ОВиК, СС): строки вида `площадь = цена`. Сейчас там ваши ориентиры: 100 → 900 000, 800 → 2 000 000, 1500 → 3 500 000, а также примерные 3000 и 5000. Поправьте точки 3000 и 5000 под реальность.
2. **Таблица разделов:** доли пакета, минимальные цены, «Себест., %» (сколько отдаёте субподрядчику с цены раздела).
3. **Себестоимость и маржа:** ГИП % от цены, налог **7** (УСН 6% + 1%), желаемая и минимальная маржа.
4. Снимите галочку **«Это расценки-пример»**.
5. **«Сохранить новую версию»**.

### 16.4. Отправка
**Настройки → Отправка.** Значения по умолчанию разумные: 30 писем в день с прогревом, окно 9–19 МСК, двойное подтверждение от 1 000 000 ₽. Ничего менять не обязательно.

✅ **Проверка:** на странице «Расценки» больше нет жёлтого предупреждения о расценках-примере.

## Шаг 18. Тестовая заявка от начала до конца

1. В панели: **Заявки → + Добавить заявку**:
   - Название: `Тест: медцентр 300 м²`;
   - Заказчик: `ООО «Тест»`;
   - Площадь: `300`;
   - **E-mail: ваш второй личный адрес** (не тот, с которого отправляете);
   - Где опубликован e-mail: `тест`.
2. **«Добавить»** → на карточке заявки нажмите **«Рассчитать»**.
3. **«Создать КП»**: через несколько секунд появится блок «Будет отправлено».
4. В Telegram придут **файл КП (PDF)** и **карточка** с кнопками. Откройте PDF и проверьте оформление и реквизиты.
5. Попробуйте **«🧮 Цены по разделам»**: ответьте, например, `АР 200000`. Через минуту придёт новая карточка.
6. Нажмите **«✅ Согласовать»**.

✅ **Проверка:** письмо с КП пришло на ваш второй адрес. Отправка работает **в рабочие дни с 9 до 19 по Москве**. Если сейчас вечер или выходные, письмо ждёт в очереди, а `/today` в боте показывает «В очереди на отправку: 1». Оно уйдёт само в начале рабочего времени.

После проверки на карточке тестовой заявки смените статус на «Отклонена», чтобы она не мешала в воронке.

## Если что-то пошло не так

| Симптом | Что сделать |
|---|---|
| Панель не открывается, ошибка сертификата | Проверьте, что `ping crm.project-med.ru` показывает IP сервера. Затем `docker compose logs --tail 50 caddy` |
| `docker compose ps`: `api` в статусе `Restarting` | `docker compose logs --tail 80 api`, пришлите вывод разработчику |
| `migrate` в статусе `Exited (1)` | Нет доступа к базе: `docker compose logs migrate`. Проверьте шаг 10.1 и `DATABASE_URL` в `.env` |
| Бот не отвечает | Шаг 17 |
| Письма не уходят | `/today` в боте: там видна причина (окно отправки, лимит, пауза, «почта не настроена»). `docker compose logs --tail 80 worker` |
| Потерян телефон с кодами | `docker compose exec api python -m app.cli reset-2fa owner` |
| Забыт пароль панели | `docker compose exec api python -m app.cli set-password owner` |

Остальное описано в `docs/RUNBOOK.md`.

# Установка на сервер (Timeweb Cloud)

Инструкция рассчитана на человека без опыта администрирования. Займёт около 40 минут.

## 0. Что понадобится

- Аккаунт Timeweb Cloud с балансом.
- Домен. Подойдёт поддомен вашего сайта, например `crm.project-med.ru` и `status.project-med.ru`.
- Telegram на телефоне.
- Приложение-аутентификатор на телефоне: Яндекс Ключ, Google Authenticator или любое другое TOTP-приложение.

## 1. SSH-ключ на вашем компьютере

Ключ нужен, чтобы входить на сервер без пароля. Так безопаснее.

**Windows 10/11:** откройте «Терминал» или PowerShell.
**macOS:** откройте приложение «Терминал».

```bash
ssh-keygen -t ed25519 -C "medproject"
```

На все вопросы нажимайте Enter. Затем выведите публичный ключ:

```bash
cat ~/.ssh/id_ed25519.pub
```

Скопируйте всю строку, начинающуюся с `ssh-ed25519`.

## 2. Сервер в Timeweb Cloud

1. Панель Timeweb Cloud → **Облачные серверы** → **Создать**.
2. Образ: **Ubuntu 24.04**.
3. Конфигурация: **2 vCPU, 4 ГБ RAM, 50 ГБ NVMe**. Меньше брать не стоит: на этапе 4 добавятся LibreOffice и распознавание сканов.
4. Регион: Москва или Санкт-Петербург.
5. В разделе **SSH-ключи** добавьте ключ из шага 1.
6. Создайте сервер и запишите его **IP-адрес**.

## 3. Домен (DNS)

У регистратора домена (или в разделе «Домены» Timeweb) создайте две A-записи на IP сервера:

| Имя | Тип | Значение |
|---|---|---|
| `crm` | A | IP сервера |
| `status` | A | IP сервера |

Записи начинают работать через 5–60 минут. Проверить можно командой `ping crm.project-med.ru`: в ответе должен быть IP сервера.

## 4. Хранилище для бэкапов (S3)

1. Timeweb Cloud → **Хранилище S3** → **Создать бакет**. Тип: приватный. Имя, например, `medproject-backups`.
2. В настройках бакета откройте **Ключи доступа** и запишите `Access Key` и `Secret Key`.
3. Запишите адрес (endpoint), обычно `https://s3.twcstorage.ru`, и регион, обычно `ru-1`. Сверьте их со страницей бакета.

## 4а. Управляемая база PostgreSQL Timeweb (если она у вас есть)

Можно использовать готовую управляемую базу Timeweb вместо базы в Docker. Плюсы: за её работой и обновлениями следит Timeweb, а данные не зависят от VPS.

1. Откройте панель Timeweb → **Базы данных** → ваша база. Проверьте **версию PostgreSQL**: нужна 14–17. Версия 18 пока не подойдёт, потому что бэкапы делает клиент PostgreSQL 17.
2. **Создайте внутри неё отдельную базу**, например `medproject`, и, по возможности, отдельного пользователя для сервиса. Существующие базы (например, от другого проекта) не трогайте.
3. **Сеть.** Создайте VPS в том же регионе и подключите сервер и базу к одной **приватной сети**: тогда база доступна по внутреннему IP и не открыта в интернет. Если приватной сети нет, используйте публичный адрес базы. Соединение всё равно шифруется (`sslmode=require`).
4. Запишите хост, порт, имя базы, пользователя и пароль. `install.sh` спросит их на шаге «База данных», если выбрать вариант **2**.

Вручную в `.env` это выглядит так:
```
COMPOSE_PROFILES=
DATABASE_URL=postgresql+psycopg://пользователь:пароль@хост:5432/medproject?sslmode=require
```
Если в пароле есть символы `@ : / ? # | &`, их нужно закодировать (`@` → `%40` и т.д.). `install.sh` делает это сам.

## 5. Вход на сервер

```bash
ssh root@IP_СЕРВЕРА
```

На вопрос `Are you sure you want to continue connecting` ответьте `yes`.

## 6. Загрузка кода

Репозиторий приватный, поэтому серверу нужен свой ключ только для чтения (deploy key).

```bash
ssh-keygen -t ed25519 -f ~/.ssh/medproject_deploy -N ""
cat ~/.ssh/medproject_deploy.pub
```

Скопируйте строку. Затем на GitHub откройте репозиторий `medproject-sales` → **Settings** → **Deploy keys** → **Add deploy key**. Вставьте строку, галочку «Allow write access» **не ставьте**.

Теперь скачайте код на сервер:

```bash
git config --global core.sshCommand "ssh -i ~/.ssh/medproject_deploy"
git clone git@github.com:Aznaur445/medproject-sales.git /opt/medproject-sales
cd /opt/medproject-sales
```

## 7. Установка одной командой

```bash
sudo ./scripts/install.sh
```

Скрипт:

- установит Docker;
- включит файрвол (наружу открыты только SSH, 80 и 443);
- включит fail2ban;
- предложит отключить вход по паролю (соглашайтесь, ключ уже настроен);
- спросит домены и e-mail;
- сгенерирует секреты в `.env`;
- запустит сервис и создаст вашего пользователя.

> ⚠️ **Сразу сохраните копию файла `.env`** в менеджер паролей (Bitwarden, KeePass, 1Password):
> `cat /opt/medproject-sales/.env`
> Без него не получится восстановить данные на новом сервере.

## 8. После установки

### 8.1. Вход в панель
Откройте `https://crm.ваш-домен`, введите логин и пароль, отсканируйте QR-код приложением-аутентификатором и введите 6 цифр.

### 8.2. Telegram-бот
1. В Telegram найдите **@BotFather** → `/newbot` → придумайте имя → получите **токен**.
2. Найдите **@userinfobot** → `/start` → он пришлёт ваш **ID** (число).
3. На сервере откройте настройки: `nano /opt/medproject-sales/.env`. Заполните `TELEGRAM_BOT_TOKEN=` и `TELEGRAM_OWNER_IDS=`. Сохраните: Ctrl+O, Enter, Ctrl+X.
4. Перезапустите сервис: `cd /opt/medproject-sales && docker compose up -d`.
5. Напишите боту `/start`, затем `/health`.

### 8.3. S3 для бэкапов
В `.env` заполните `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, затем выполните `docker compose up -d`. Проверка:

```bash
./scripts/backup.sh
```

В ответе должен появиться бэкап в разделах `local` и `s3`.

### 8.4. Внешний мониторинг (Uptime Kuma)
1. Откройте `https://status.ваш-домен` и создайте администратора (отдельный пароль).
2. **Settings → Notifications → Setup Notification → Telegram.** Вставьте токен бота и ваш ID, нажмите «Test».
3. **Add New Monitor:**
   - тип HTTP(s), URL `https://crm.ваш-домен/health`, интервал 60 с, уведомление Telegram;
   - второй монитор: тип HTTP(s), URL `http://api:8000/health/live` (проверка изнутри, минуя HTTPS).

### 8.5. Проверка восстановления из бэкапа (обязательно один раз)

```bash
./scripts/backup.sh                       # сделать бэкап и увидеть его метку, например 20261003-120000
./scripts/restore.sh 20261003-120000      # восстановить (на вопрос ответить ДА)
```

После восстановления войдите в панель и проверьте журнал действий: записи на месте.

### 8.6. Проверка автозапуска
```bash
reboot
```
Через 2–3 минуты откройте панель. Сервис должен подняться сам, а в Telegram не должно быть сообщений о сбоях.

### 8.7. Почта для отправки КП
Рекомендуется ящик на вашем домене, например `kp@project-med.ru`, через VK WorkSpace (Mail.ru для бизнеса). Личный `@bk.ru` для рассылок подходит плохо: на нём нельзя настроить SPF/DKIM для своего домена, лимиты ниже, а за письма незнакомым адресатам его могут заблокировать.

1. В настройках почтового ящика: **Безопасность → Пароли для внешних приложений → Добавить** (доступ SMTP и IMAP). Скопируйте пароль.
2. В `.env` укажите:
   ```
   MAIL_USER=kp@project-med.ru
   MAIL_APP_PASSWORD=пароль_приложения
   MAIL_FROM_NAME=МедПроект
   ```
3. `docker compose up -d`.
4. Проверка: создайте заявку на свой второй адрес, согласуйте КП и убедитесь, что письмо пришло. Если сейчас выходной или вне окна 9–19 МСК, письмо будет ждать в очереди.

Настройка SPF, DKIM и DMARC для домена подробно описана на этапе 5.

## Обновление

Обновление запускается только вашей командой:

```bash
cd /opt/medproject-sales && ./scripts/update.sh
```

Перед обновлением скрипт сам делает бэкап.
